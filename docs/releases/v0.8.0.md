# Issue to Merge v0.8.0

Prepared on 2026-10-28. This is a release candidate until its PR is merged and the
tag/release is published. CI status belongs to the current PR HEAD.

[English](#english) | [简体中文](#简体中文)

## English

### Changes

- Add explicit `full` and `quick` delivery modes. Full remains the default;
  quick keeps an independent first review and re-reviews material behavior or
  contract changes. Model complexity is a separate choice.
- Make Copilot an independent `auto|off` option. Auto uses an available initial
  PR review or records unavailability/timeout; off skips only Copilot and its
  wait. Both modes allow one request at the first Ready HEAD and one feedback
  snapshot. Later fixes/pushes cannot start a delayed first request or a repeat.
- Preserve local review, configured Judge gates, current-HEAD CI, thread
  dispositions, branch protection, and cleanup when Copilot is unavailable.
- At the last allowed local review, complete required adjudication and the same
  worker's tested final fix, then commit without another local round. Record the
  fix as unreviewed, never as reviewer PASS; retain checks and authorization.
- Add a selectable TypeSafe `jev-latest` Judge route and its structured local/
  remote review assessments. These live calls require that strict route and
  `TYPESAFE_API_KEY`. Existing non-TypeSafe routes and the opt-in retrospective
  shadow pilot remain available; a key alone does not select a new provider.
- Shorten both READMEs and add mode examples, Copilot options, a model guide and
  the explicit statement that no extra hook is required.

### Upgrade and limits

Keep external runtime selections, host evidence, Issue state and local changes
outside the package replacement. Use a clean v0.8.0 checkout after publication;
do not overwrite a dirty installation. Runtime configuration remains schema 2
and Issue state remains schema 3. Existing counters and history are preserved;
legacy Ready history can supply the initial HEAD. No new Python dependency is
required.

TypeSafe assessment recording applies only to a selected strict `typesafe-ai` Judge.
Other providers keep their configured independent Judge and omit TypeSafe-only
state commands. Inputs/results stay outside the checkout. Selecting TypeSafe
sends the supplied evidence to that service; it does not inspect code or replace
the independent reviewer, manager verification or repository merge gates.

Tests use local service fixtures, including an explicit test-only credential for
the positive TypeSafe preflight case and a missing-key rejection case. CI targets
Python 3.10 and 3.11 without live service credentials. These checks do not prove
live Codex/Hermes dispatch, Copilot availability or TypeSafe judgment accuracy.

### Merge and publish checklist

1. Confirm the PR's latest HEAD has passing required checks, independent local
   review and final dispositions for review threads. Copilot is requested only
   once, at initial PR publication, if available.
2. Merge through the normal protected PR path. Do not publish from the unmerged
   branch or create the release tag before merge.
3. Read the PR's actual merge commit SHA and confirm that it is on `main`.
4. Create `v0.8.0` targeting that exact merge SHA and use this file as the release
   body. Check the published tag target and release URL.

```shell
gh pr checks <PR_NUMBER> --repo ferryhe/issue-to-merge
gh pr merge <PR_NUMBER> --repo ferryhe/issue-to-merge --squash --match-head-commit <REVIEWED_PR_HEAD>
gh pr view <PR_NUMBER> --repo ferryhe/issue-to-merge --json mergedAt,mergeCommit
gh release create v0.8.0 --repo ferryhe/issue-to-merge --target <MERGE_COMMIT_SHA> --title "Issue to Merge v0.8.0" --notes-file docs/releases/v0.8.0.md --latest
```

These are maintainer steps, not actions performed by preparing this candidate.
GitHub's standard source archives are sufficient; no separate asset is required.

## 简体中文

### 本次变化

- 新增明确的 `full/quick` 模式。普通模式保持默认；quick 至少完成一次独立审核，
  后续只有行为或数据契约发生实质变化才复审。模型难度单独选择。
- Copilot 改为独立的 `auto/off` 选项。能用则使用初次 PR 审核，不可用或超时则
  记录原因继续；off 不请求也不等待。每个 PR 只在首次 Ready 的 HEAD 请求一次，
  只抓取一次反馈；后续修复和推送既不能补启动首次请求，也不能重复请求。
- Copilot 关闭不跳过本地审核、所选 Judge、当前 HEAD 的 CI、thread 处理、分支
  保护或清理。
- 到达本地审核上限后，完成必要判断，由同一 worker 修复并验证后提交，不增加
  下一轮审核，也不把最终修复记成 reviewer PASS。
- 新增可选择的 TypeSafe `jev-latest` Judge 及逐轮结构化评估。只有选用该路由才
  执行相应实时 API 调用，并要求 `TYPESAFE_API_KEY`；其他 provider 和原有的
  可选回溯试点保留，仅提供 key 不会切换 provider。
- 精简中英文 README，补充调用示例、Copilot 选项、模型配置指南和无需额外 hook
  的说明。

### 升级与验证

正式发布后使用干净的 v0.8.0 checkout 安装；备份本地修改，保留包目录外的运行时
选择、主机证据和 Issue 状态。配置仍为 schema 2，状态仍为 schema 3，不重置历史
或审核计数；旧 Ready 历史可以恢复初始 HEAD。没有新增 Python 依赖。

只有所选 Judge 是 `typesafe-ai` 时，才使用 TypeSafe 专用状态命令；其他 provider
继续使用自己的 Judge 路由。真实 TypeSafe 调用会发送所提供的证据，不替代独立
reviewer、manager 核查或合并门槛。

测试使用本地服务 fixture，正向 preflight 使用明确的测试值，同时验证缺 key 会被
拒绝。CI 覆盖 Python 3.10/3.11，不需要真实服务凭据；这些测试不证明真实模型派发、
Copilot 可用性或 TypeSafe 判断准确率。

正式合并前，核实当前 PR HEAD 的检查、独立审核和 thread 处理均完成；按上方清单
合并后，读取真正的 merge commit SHA，再以该 SHA 创建 `v0.8.0` Release。准备候选
版本本身不代表已执行正式合并、打标签或发布。
