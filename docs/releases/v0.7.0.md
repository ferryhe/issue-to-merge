# Issue to Merge v0.7.0

Release date: 2026-09-29

[English](#english) | [简体中文](#简体中文)

## English

v0.7.0 adds an optional retrospective TypeSafe pilot for evaluating already
completed review findings. The pilot records model judgments beside final human
dispositions so maintainers can measure agreement before considering any live
use.

### Highlights

- `scripts/typesafe_shadow.py` batches three narrow judgments per finding:
  acceptance-criterion mapping, reproduction evidence, and preliminary policy
  disposition.
- Human labels are omitted from the TypeSafe request and retained separately in
  the result. The output records typed answers, probabilities, confidence when
  available, model, usage, and packet/request hashes.
- The pilot is disabled by default. An API key alone does not activate it, and
  predictions cannot change review decisions, review counts, Judge triggers,
  acceptance criteria, or merge gates.
- The helper uses Python's standard library and adds no required dependency.

### Limits and data handling

The helper evaluates only the text and evidence supplied in its packet. It does
not find code locations, execute reproductions, or decide whether a PR is ready.
Send only relevant, sanitized evidence; the packet content is sent to TypeSafe.
Keep packet and result files outside the skill and target checkouts.

The TypeSafe assessment used to shape this pilot is an initial signal, not an
accuracy study. Do not set confidence thresholds from it. Compare predictions
with representative final human labels, track false-valid, false-invalid, and
uncertain outcomes separately, and analyze English and CJK results separately.

### Validation

All 54 local unit tests pass. Repository CI targets Python 3.10 and 3.11; its
status is reported by the release PR. These checks do not measure TypeSafe's
accuracy on project findings.

### Install

Python 3.10 or newer is required.

```shell
git clone --branch v0.7.0 --depth 1 https://github.com/ferryhe/issue-to-merge.git
```

Register the cloned repository root with the runtime's skill installation
mechanism. GitHub's standard source archives are sufficient; there is no separate
release asset.

### Upgrade from v0.6.0

Back up local edits and use a clean checkout of v0.7.0. Preserve external runtime
selections and Issue state files. No state migration or new Python dependency is
required. TypeSafe remains disabled unless a manager is explicitly assigned
`retrospective-only`; setting `TYPESAFE_API_KEY` alone does not enable API calls.

## 简体中文

v0.7.0 增加了可选的 TypeSafe 回溯试点，用于评估已经完成人工判断的审查意见。它会
把模型判断和最终人工结论并列保存，供维护者先评估一致性，再决定是否考虑实时影子评估。

### 主要变化

- `scripts/typesafe_shadow.py` 会为每条 finding 批量提交三个窄范围判断：是否对应验收
  标准、复现证据是否充分，以及初步策略分类。
- TypeSafe 请求不会包含人工标签；结果会将标签与模型预测分开保存，并记录结构化答案、
  概率、可用时的置信度、模型、用量及请求和数据包哈希。
- 试点默认关闭。仅设置 API key 不会启动调用；预测不能改变审查结论、审查计数、Judge
  触发条件、验收结果或合并门槛。
- 脚本只使用 Python 标准库，不增加必需依赖。

### 限制与数据处理

脚本只评估数据包中提供的文本和证据，不会定位代码、执行复现或决定 PR 是否可合并。只
发送相关且已清理的证据；数据包内容会发送给 TypeSafe。输入和结果文件都应保存在 skill
与目标 checkout 之外。

用于制定本试点的 TypeSafe 判断只是初步信号，不是准确率研究。不要据此设置置信度阈值。
请用有代表性的最终人工标签比较预测结果，分别统计误判为有效、误判为无效和不确定的
结果，并分别分析英文和中文输入。

### 验证

本地 54 项单元测试全部通过。仓库 CI 使用 Python 3.10 和 3.11；其状态会显示在发布
PR 中。这些检查也不衡量 TypeSafe 在本项目 finding 上的准确率。

### 安装

运行要求为 Python 3.10 或更高版本。

```shell
git clone --branch v0.7.0 --depth 1 https://github.com/ferryhe/issue-to-merge.git
```

然后通过运行时的 skill 安装机制注册克隆仓库的根目录。GitHub 标准源码归档即可，无需
单独的 release 附件。

### 从 v0.6.0 升级

备份本地修改，并使用 v0.7.0 的干净 checkout。保留外部运行时选择和 Issue 状态文件。
无需迁移状态，也不新增 Python 依赖。只有 manager 被明确指定为 `retrospective-only`
时才会运行 TypeSafe；仅设置 `TYPESAFE_API_KEY` 不会启用 API 调用。
