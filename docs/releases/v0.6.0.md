# Issue to Merge v0.6.0

Release date: 2026-09-13

[English](#english) | [简体中文](#简体中文)

## English

v0.6.0 adds portable runtime onboarding, an optional tiered Codex policy, durable
Hermes Profiles/Kanban execution, tighter context isolation, and a current-HEAD
review-thread merge gate. It preserves the v0.5.0 lifecycle for existing states
unless a new Issue is initialized with a selected strict runtime snapshot.

### Highlights

- [PR #15](https://github.com/ferryhe/issue-to-merge/pull/15) adds the Hermes
  Profiles/Kanban adapter. Hermes profiles remain authoritative for provider,
  model, and tool state. Re-dispatch keeps the same durable worker card, profile,
  provider, and model with complete task context. Lifecycle commands record and
  verify worker/reviewer identity, profile, provider, and model.
- [PR #16](https://github.com/ferryhe/issue-to-merge/pull/16) moves each Hermes
  Issue into a fresh isolated orchestrator manager. The main chat manages only the
  queue and verifies compact results; detailed reports and test evidence stay in
  external files. The adapter documents delegation depth, timeout, compression,
  and context-budget boundaries.
- [PR #17](https://github.com/ferryhe/issue-to-merge/pull/17) requires a fresh
  query showing zero unresolved inline review threads for the current PR HEAD
  before merge. A new PR head invalidates older thread and check evidence.
- [PR #18](https://github.com/ferryhe/issue-to-merge/pull/18) adds first-use
  runtime/routing selection, saved external preferences, actual-host preflight,
  frozen per-Issue snapshots, and the optional strict Codex lifecycle. It also
  preserves explicit inheritance and provides an explicit migration path for
  legacy `config/models.json` mappings.

### Optional tiered Codex routes

| Work | Role | Model | Reasoning |
| --- | --- | --- | --- |
| Issue control | manager | gpt-5.6-sol | medium |
| Research | researcher | gpt-5.6-luna | low |
| Code exploration | explorer | gpt-5.6-luna | medium |
| Simple/normal implementation | worker | gpt-5.6-terra | medium |
| Complex implementation | senior_worker | gpt-5.6-sol | high |
| Extreme implementation | expert_worker | gpt-6-astra | high |
| Local review | reviewer / senior_reviewer | gpt-5.6-sol | high |
| Adjudication and architecture | judge / architect | gpt-6-astra | high |

This preset allows up to four child agents and requires Fast mode off. It applies
only when selected; current and custom users keep their chosen limits and routes.

The strict policy records a pre-implementation assessment before selecting the
worker tier, keeps the same worker through all fixes, and gives every local review
to a fresh independent Sol/high reviewer. A separate Astra/high Judge handles the
second and every later completed changes review, declared reviewer disagreements,
and unresolved architecture/security uncertainty. A Judge decision does not
replace the required reviewer PASS. If the review limit is reached without PASS,
the Issue remains blocked.

Current routing remains an inheritance choice: the saved external preference keeps
its null values, while each Issue preflight binds fresh inspected routes into that
Issue's snapshot. Returning runs reuse the saved choice unless the customer changes
it. Custom routing can retain the legacy lifecycle or opt into the complete strict
assessment/Judge/PASS policy.

Hermes requires installed profile/provider/model evidence, nested delegation, and
`max_spawn_depth >= 2` for its isolated manager and children. The shipped Hermes
configuration contains examples, not claims about profiles installed on a host.

### Validation and limits

The local suite passes all 50 tests, including the 30 tests that predate PR #18.
Repository CI is configured for Python 3.10 and 3.11; this note does not claim a
release-head CI result before that run completes. These tests validate configuration
and lifecycle contracts, not live Codex or Hermes model execution. Host capability
evidence is inspected input supplied to preflight and must reflect the actual host.

### Install

Python 3.10 or newer is required for the runtime and lifecycle helpers.

```shell
git clone --branch v0.6.0 --depth 1 https://github.com/ferryhe/issue-to-merge.git
```

Register the cloned repository root with the runtime's skill installation
mechanism. This release uses GitHub's standard source archives and has no separate
asset.

### Upgrade from v0.5.0

Back up the old installation before replacing it, including any customized
`config/models.json`. Preserve external `runtime-selection.json` files and Issue
state files. Use a clean clone or clean checkout for v0.6.0; do not overwrite a
dirty installation.

If the old `config/models.json` contains custom mappings, run the **new v0.6.0
helper** against the **backed-up old file**, review the generated candidate, and
select it explicitly:

```shell
python scripts/runtime_config.py migrate-legacy --legacy /backup/v0.5.0/config/models.json --runtime codex --output /external/migrated-runtime.json
python scripts/runtime_config.py select --selection /external/runtime-selection.json --runtime codex --strategy custom --config /external/migrated-runtime.json
```

Do not migrate from the new package's all-null `config/models.json`; it contains no
old custom values. Existing states without a runtime snapshot retain the legacy
lifecycle. Assessment, conditional Judge, and mandatory PASS gates activate only
for new Issues initialized from a ready snapshot whose strict policy was explicitly
selected. Saved external routing preferences survive later package replacements.

The helper validates supplied host evidence before dispatch. It does not discover
capabilities, edit global Codex/Hermes configuration, or silently substitute an
unavailable model. See the
[runtime selection and upgrade contract](https://github.com/ferryhe/issue-to-merge/blob/v0.6.0/references/runtime-selection.md),
[Codex adapter](https://github.com/ferryhe/issue-to-merge/blob/v0.6.0/references/codex-runtime.md),
[Hermes adapter](https://github.com/ferryhe/issue-to-merge/blob/v0.6.0/references/hermes-runtime.md),
and [runtime onboarding audit](https://github.com/ferryhe/issue-to-merge/blob/v0.6.0/docs/audits/runtime-onboarding-2026-09-13.md).

## 简体中文

v0.6.0 增加了可移植的运行时 onboarding、可选的 Codex 分层策略、可持续执行的
Hermes Profiles/Kanban 适配、更严格的上下文隔离，以及针对当前 PR HEAD 的
review thread 合并门禁。已有状态默认继续使用 v0.5.0 兼容流程；只有使用新选择的
严格运行时快照初始化的新 Issue 才启用严格生命周期。

### 主要变化

- [PR #15](https://github.com/ferryhe/issue-to-merge/pull/15) 增加 Hermes
  Profiles/Kanban 适配。Hermes profile 继续决定 provider、model 和工具状态；
  重新派发时复用同一 durable worker card、profile、provider 和 model，并携带
  完整任务上下文。生命周期命令会记录并核验 worker/reviewer 的身份和路由。
- [PR #16](https://github.com/ferryhe/issue-to-merge/pull/16) 为每个 Hermes Issue
  创建独立的 orchestrator manager。主对话只管理队列并核验精简结果；完整报告
  和测试证据保存在外部文件。适配文档明确了委派深度、超时、压缩和上下文预算。
- [PR #17](https://github.com/ferryhe/issue-to-merge/pull/17) 要求合并前重新查询，
  确认当前 PR HEAD 的未解决行内 review thread 为零。PR HEAD 变化后，旧 thread
  证据会失效。
- [PR #18](https://github.com/ferryhe/issue-to-merge/pull/18) 增加首次运行时/路由
  选择、安装目录之外的偏好保存、真实主机预检、每个 Issue 的固定快照，以及
  可选的严格 Codex 生命周期。同时保留显式继承，并为旧 `config/models.json`
  映射提供显式迁移路径。

### 可选的 Codex 分层路由

| 工作 | 角色 | 模型 | 推理强度 |
| --- | --- | --- | --- |
| Issue 控制 | manager | gpt-5.6-sol | medium |
| 调研 | researcher | gpt-5.6-luna | low |
| 代码探索 | explorer | gpt-5.6-luna | medium |
| 简单/普通实现 | worker | gpt-5.6-terra | medium |
| 复杂实现 | senior_worker | gpt-5.6-sol | high |
| 极复杂实现 | expert_worker | gpt-6-astra | high |
| 本地审查 | reviewer / senior_reviewer | gpt-5.6-sol | high |
| 裁决与架构分析 | judge / architect | gpt-6-astra | high |

该预设最多允许四个子代理，并要求关闭 Fast mode。只有用户明确选择时才会应用；
当前设置和自定义用户继续使用自己选择的上限和路由。

严格策略会在选择 worker 层级前记录实现前评估，在所有修复中保留同一 worker，
并让每轮本地审查使用全新的独立 Sol/high reviewer。第二次及以后完成的 changes
审查、明确的 reviewer 分歧，或未解决的架构/安全不确定性，由独立 Astra/high
Judge 处理。Judge 结论不能代替 reviewer PASS；达到审查上限仍无 PASS 时，
Issue 会保持阻塞。

当前路由仍是一种继承选择：保存在安装目录之外的偏好保留 null，而每个 Issue 的
预检会把新检查到的具体路由写入该 Issue 的固定快照。后续运行复用已保存的选择，
除非客户明确修改。自定义路由可以保留兼容生命周期，也可以选择完整的严格
assessment/Judge/PASS 策略。

Hermes 必须提供已安装 profile/provider/model 的证据，启用嵌套委派，并满足
`max_spawn_depth >= 2`，才能创建隔离 manager 及其子代理。包内 Hermes 配置只是
示例，不代表主机已经安装这些 profile。

### 验证与限制

本地测试共 50 项，全部通过，其中包括 PR #18 之前已有的 30 项测试。仓库 CI
配置为 Python 3.10 和 3.11；在新 release HEAD 的 CI 实际完成前，本说明不宣称
该结果已通过。这些测试核验配置与生命周期契约，不证明 Codex 或 Hermes 模型
已经在真实环境执行。主机能力证据是传给 preflight 的已检查输入，必须反映实际
主机状态。

### 安装

运行时和生命周期脚本要求 Python 3.10 或更高版本。

```shell
git clone --branch v0.6.0 --depth 1 https://github.com/ferryhe/issue-to-merge.git
```

然后通过运行时的 skill 安装机制注册克隆仓库的根目录。本版本使用 GitHub 标准
源码归档，没有单独的附件。

### 从 v0.5.0 升级

替换旧安装前，请备份整个旧安装，包括自定义的 `config/models.json`。保留外部
`runtime-selection.json` 和 Issue 状态文件。请使用干净的克隆或 checkout 安装
v0.6.0，不要覆盖有未提交修改的安装目录。

如果旧 `config/models.json` 包含自定义映射，请用 **v0.6.0 的新脚本**读取
**备份的旧文件**，检查生成的候选配置，再显式选择：

```shell
python scripts/runtime_config.py migrate-legacy --legacy /backup/v0.5.0/config/models.json --runtime codex --output /external/migrated-runtime.json
python scripts/runtime_config.py select --selection /external/runtime-selection.json --runtime codex --strategy custom --config /external/migrated-runtime.json
```

不要从新安装中全为 null 的 `config/models.json` 迁移，因为其中没有旧自定义值。
没有运行时快照的旧状态继续使用兼容生命周期。assessment、条件 Judge 和强制
PASS 门禁只会应用于显式选择严格策略、并用 ready 快照初始化的新 Issue。保存在
安装目录之外的路由偏好在以后替换包时仍会保留。

脚本会在派发前核验调用方提供的主机证据，但不会自动发现能力、修改 Codex/Hermes
全局配置，或静默替换不可用模型。详见
[运行时选择与升级约定](https://github.com/ferryhe/issue-to-merge/blob/v0.6.0/references/runtime-selection.md)、
[Codex 适配说明](https://github.com/ferryhe/issue-to-merge/blob/v0.6.0/references/codex-runtime.md)、
[Hermes 适配说明](https://github.com/ferryhe/issue-to-merge/blob/v0.6.0/references/hermes-runtime.md)和
[运行时 onboarding 审计](https://github.com/ferryhe/issue-to-merge/blob/v0.6.0/docs/audits/runtime-onboarding-2026-09-13.md)。
